## 三、意图识别

评测集 94 条（7 类，含 unknown 与 unsafe 负样本），规则模式结果：

| 指标 | 值 |
|---|---|
| Accuracy | 1.0000 |
| Macro-F1 | 1.0000 |
| 各类 P/R/F1 | 均为 1.0（after_sales / order_query / policy_qa / product_advice / smalltalk / unknown / unsafe） |

**必须说清的局限**：这是规则分类器在自建评测集上的结果，且规则是按这批用例的失败样例迭代出来的（初始 0.8723 → 12 个错例定位 → 0 错例）。它证明的是"链路与判定逻辑正确"，不能当作泛化能力。接上真实 LLM 后应由模型做主体判定，规则只兜底。

## 四、检索质量（60 条属性约束查询，弱标注）

同一套硬过滤条件下三档对比：

| 方案 | Recall@10 | NDCG@10 | MRR |
|---|---|---|---|
| BM25 单路 | 0.9950 | 0.9879 | 0.9806 |
| 混合（BM25+向量，RRF 加权） | 0.9867 | 0.9868 | **1.0000** |
| 混合 + 业务精排（系统实际输出） | 0.9392 | 0.9404 | 0.9722 |

解读：

- 加权 RRF（BM25 权重 1.6 / 向量 1.0）把混合检索的首位命中率拉到 **MRR=1.0**，召回与纯词法基本持平（-0.0083）。
- 初始等权 RRF 时召回掉到 0.93、NDCG 0.9458，说明通道权重对结果影响显著，必须实测调参而不是拍脑袋。
- 业务精排再降召回（-0.047），这是**设计取舍**：库存/销量/评分/预算贴合会牺牲部分相关性换转化，报告里单列，不混算。
- 评测集的 query 直接包含属性词，属 BM25 友好场景；真实用户口语化表述下向量的价值会更大，本报告不给这个结论，因为没测。

## 六、端到端与压测

### 6.1 单请求（进程内直调图）

### 6.4 限流验证

单用户 1 分钟内超过 30 次 → 返回 429（首轮误用同一用户压测时命中 81% 429，恰好验证限流生效）。这不是缺陷，是设计行为；生产环境阈值应按套餐分级。

## 七、结论

1. 功能链路完整：导购、订单、售后预审、政策问答四类主路径均通，SSE 事件序列完整。
2. 安全红线有效：越权、注入、重复提交、未确认执行、版本冲突全部被拦。
3. 质量指标可用：政策引用 Top-1 100%，混合检索首位命中 100%，意图判定在自建集上无错。
4. **性能瓶颈明确**：CPU 上跑 BGE-M3 编码，并发 20 时 P95 从 322 ms 涨到 3.65 s，吞吐只有 9 rps。这是单机 CPU 的物理上限，不是代码问题；上 GPU 或换轻量向量模型（bge-small）可解。
5. **不确定性必须写在简历之外**：LLM 模式（真实 Key）尚未跑过，规则模式的语义泛化能力有限；生产容量结论不能引用本机压测。
