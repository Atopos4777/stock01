# ADR-001 架构决策记录

## 决策 1：单 Orchestrator + 确定性子图，不拆多 Agent

- **背景**：导购、订单、售后三个域共享身份、会话与审计；没有独立团队维护，也没有独立扩缩容需求。
- **决策**：一个 Orchestrator（LangGraph StateGraph）+ 三个确定性子流程；不引入跨 Agent 路由与状态同步。
- **代价**：单进程内耦合度略高；后续若要拆，需先引入事件总线与独立部署。
- **触发拆分条件**：业务域由不同团队维护、生命周期独立、确需自治与独立扩缩容。

## 决策 2：不接入 A2A，MCP 只做只读演示

- **背景**：供应商、物流都是明确 API，不存在"独立自治 Agent"边界。
- **决策**：核心链路用受控函数工具；仅暴露 2–3 个只读 MCP 工具证明可复用性，写操作仍走网关。
- **理由**：为追热点硬上 A2A 会引入认证、任务状态、幂等与故障处理成本，收益无法证明。

## 决策 3：SQLite 替代 PostgreSQL + pgvector（PoC 适配）

- **背景**：目标机器未装数据库服务，PoC 要求一条命令启动。
- **决策**：SQLite 存结构化数据；BM25 用 rank-bm25，向量用 numpy 余弦；向量矩阵落盘缓存。
- **上限**：2,000–10,000 SKU 下检索毫秒级；百万级或复杂聚合需迁移 OpenSearch + 专用向量库。
- **替换点**：`app/db/session.py` 的 URL 与 `app/retrieval/index.py` 的向量检索实现。

## 决策 4：进程内缓存替代 Redis

- **背景**：免装服务；只需要会话状态、限流、短缓存与幂等表。
- **决策**：`TTLCache` 与 `IdempotencyStore` 保持与 Redis 同签名接口，便于替换。
- **风险**：多实例部署时幂等失效，必须换 Redis 或数据库唯一约束。当前 SQLite 的 `idempotency_key` 唯一约束已作为第二道防线。

## 决策 5：BGE-M3 失败自动降级哈希向量

- **背景**：国内网络下载 2.2GB 模型不稳定；不能因此让系统起不来。
- **决策**：`EMBEDDING_MODE=auto` 先试 BGE-M3，失败降级字符 n-gram 哈希向量，并在 `/api/health` 与评测报告中显式标注。
- **红线**：哈希模式下的检索指标不得当作语义效果对外宣称。

## 决策 6：退款资格与金额由规则引擎裁决

- **背景**：LLM 读政策文本会漏条件、会编例外，且无法回归测试。
- **决策**：`after_sales_rules.evaluate()` 纯函数、版本化、可单测；LLM 只做解释与缺参收集。
- **验证**：`tests/test_rules_and_retrieval.py` 覆盖时限、品类例外、高价值、金额不来自文本。

## 决策 7：SSE 走应用层分块

- **背景**：PoC 阶段 LLM 调用为同步请求，节点执行完才有完整回答。
- **决策**：先回放节点状态事件，再把回答按块推送；不伪造 token 级流式。
- **影响**：报告中的 TTFT 是"首个文本块到达时间"，不等于模型首 token 延迟。真流式需要把 LLM 调用改为流式并改写节点为异步生成器。
